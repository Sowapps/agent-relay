One experiment completed on Codex 0.167.0-alpha.4.1 in 2.718 seconds, with zero model turns and zero reload RPCs. Both fixture generations used the same Python protocol implementation with different generation arguments; the decisive new fact is process lifetime/stream behavior, not a production release upgrade.

## Initial migration trace and supported boundaries

Source trace of current McpBroker: Monitor understands its existing close marker and runtime/catalog change notification. Run calls EnsureWorker; that creates a worker with redirected private pipes, then forwards replies through the broker-owned original stdout. DropWorker kills/disposes that child. BoundedLines has its own read buffer. There is no cooperative original-handle export, successor startup or initialized-state/buffer transfer hook. The new result therefore cannot be retrofitted by merely changing runtime metadata or placing a new worker on disk. Required generic tools are also absent from the client's already-cached initial surface.

Neither establishes an externally callable reload of this actual desktop or the exact meaning/availability of that UI action in the operator's installed build. Do not give an invented click path or assert that toggling a switch will reconnect this chat. The already-qualified config/mcpServer/reload method can do it only through the owning backend.

Read-only installed-app source inspection found internal use of config/mcpServer/reload after plugin maintenance. Its presence is not an exposed control API.
