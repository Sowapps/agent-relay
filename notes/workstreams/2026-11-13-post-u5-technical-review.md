## Findings and distinctions

1. **Confirmed static startup gap, actual enabled-registry case not executed:** McpTransportInstallation.PowerShell now prefers standalone PowerShell 7. An existing generic entry may name the previously resolved bundled executable (observed in the U5 before-capture). StartupRegistration.Capture accepts only today's generated command and the older startup-launcher command; a valid prior generic command with a different PowerShell path is rejected before reconciliation. Disabled actual fixtures and fake legacy/current tests do not cover that case. Fix must recognize only the reviewed prior common-entry command and exact owned script, never bless arbitrary Run values. Keep rollback's exact value/kind and the user's opt-in. Long command refusal remains intentional; qualify the real intended path length without writing the real registry.
2. **Confirmed static rollback inconsistency, not a repeated live failure:** forward TransportsReady accepts a confirmed closed/dead required process and checks gateway/selected/active worker identities. CompleteSelectedRollback has separate weaker identity logic but insists every recorded instance be current. A client safely closed during recovery can therefore leave files_restored suspended indefinitely. Share the readiness invariant with an explicit target selection; do not retire a live stale/unresponsive holder or ignore a missing identity. Check rollback and forward together.
3. **Plausible continuation races/liveness gap:** parent Start writes starting after launching the child, which can overwrite a newer running/complete publication; Presence returns retained state without projecting process liveness. An abruptly killed runner can remain displayed as running. Start's launch lock and an external simultaneous resume may also surface sharing conflicts as storage errors. No corruption/lost work reproduced. Model one owner for lifecycle publication, classify contention explicitly and keep status passive; never clear the barrier or replay work to make progress look healthy.
4. **Confirmed static tooling gap, combined command not rerun:** isolated-delivery.py qualify still calls test-mcp-startup.py and deployment-acceptance.py; both call list_projects as a top-level tool. The new exported launch has exactly four tools, so those old typed calls cannot qualify it. U5's new selected-package.py proves the missing same-open-client seam, but is not yet routed from the existing one-command qualification workflow. Integrate that adapter into the owner and route generic versus retained legacy probes explicitly. Do not build a second updater or silently discard the old history/refusal checks.
5. **Unresolved actual-client boundary:** AR-CLIENT-09 / AR-CFG-10 retain the failed desktop Restart loop and settings-writer race. U5 same-stdio succession solves subsequent generic updates, not the initial legacy attachment. Read-only exposed Codex tool-name inspection found no dedicated MCP reload/restart action; this is a bounded tool inventory observation, not a claim about all possible client internals. Do not repeat the failed UI action or invent a reachable owning socket. Prepare exact shared registration before/after diff and one coordinated initial migration with rollback; separately authorize actual activation.
6. **Process/measurement gaps and investigation candidates:** historical tracked goal is unfinished/blocked with unrelated counters; tools expose no rename/delete/reactivate. Do not falsely complete the rollout to allocate a slot. Shared account weekly observations exist, but exact per-lot tokens do not. U5 report needs automatic client executable/version, phase timings and runtime artifact sizes, with all probes using its isolated CODEX_HOME. Empty Codex homes also cause unrelated plugin-cache/network attempts and long-path noise. Tool discovery twice matched the common mcp namespace and printed irrelevant metadata: filter stripped tool names first, cap the projection and read only needed schemas. These are concrete process improvements; no fabricated token/performance gain. Duplicate image verification across host/worker and package/runtime storage cost are investigation candidates only; measure before caching or changing safety checks.

Avast signing/reputation and historical WSL launcher timing remain separate retained issues, without new causal attribution or permission to change system security/restart WSL. Unsupported resources/templates/list generates a client warning but did not block U5; assess only if it causes repeated user-facing noise. Fictional storage cleanup in the prototype remains design-only; this TR does not authorize implementing it.

## Reusable execution and failure protocol

For each approved lot, refine its point plan at the actual checkpoint: owner/complementary operation, exact delta/exclusions, important failure and one decisive check. Reuse unchanged U3/U4/U5 proof. Keep the dedicated branch and source integration process; preserve existing data and no-replay semantics. Put a failing case in the open register before broadening tests. Package only after meaningful runtime changes; retain source-input hashes, full result/protocol and sanitized operator summary. Do not repeatedly run model/WSL/client reload experiments.

On contention, return a clear in-progress/conflict outcome and retain the original transaction. On uncertainty, preserve admission and diagnostic; do not clear locks by hand. On interrupted recovery, validate retained image/scope and process lifetime before continuation. Before any rollback after possible reopening, preserve the existing refusal protecting new work. On actual-client control failure, stop that activation boundary and continue only independently approved source work. Never claim a fresh client proves an old chat migrated.
