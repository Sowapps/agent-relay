Agent Relay — get started with your usual agent

Utility: Connect agents through the Model Context Protocol (MCP) across Windows and Windows Subsystem for Linux (WSL), and monitor project activity.
Usage: Ask your usual agent for help; preserve your rules and approve the intended preparation scope first.

IF YOU START IT YOURSELF

1. Extract the complete ZIP to a persistent writable installation folder.
2. Run Initialize-Relay.cmd once, then Start-AgentRelay.cmd.
3. The default relay configuration/history stays in data/. Your actual Windows/Linux project workspaces are separate existing folders, not this installation or data directory.
4. A relay project connects participants, their workspaces and permissions. Select it in the application to monitor tasks, messages, results and sessions. Your requesting agent's Windows client connects through MCP; the relay delegates to supported native agent clients in WSL. The current application interface is in French.

The .NET runtime is included for Windows startup/direct MCP. The portable guide covers WebView2 and any Python/WSL/native-client prerequisites needed for your task. Nothing is installed globally or registered to start automatically. Current boundaries, practical handling and future options are in app/documentation/limits.md.

Closing the window hides it; use the tray to reopen, and Quitter to exit. Keep the chosen relay running for MCP. A different data directory is another instance. To move or upgrade, stop the selected host, back up its data and keep the old version until verification. Ask your agent to retain the exact data scope and regenerate/review the MCP fragment if paths change. Never put credentials/history into a repository or release asset.
