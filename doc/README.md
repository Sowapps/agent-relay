# Documentation

**Utility:** provides the entry point to the project's documentation and durable target.  
**Usage:** read when locating a project concept, documentation rule or agreed product requirement.

## Reading the documentation

The activity documentation describes what exists and how to work with it. The target describes what the product must be, including capabilities that have no implementation. A target statement is
not a claim of delivery or feasibility demonstrated by a test.

## Activities

- [Developing](developing/README.md): common organization, workflow and conventions.
- [Documenting](documenting/README.md): documentation ownership and maintenance.
- [Operating](operating/README.md): prerequisites and main commands.
- [Agent Relay documentation](../apps/agent-relay/doc/README.md): application vocabulary, experiments and target.

Only activities with content have directories. The complete activity vocabulary remains using, developing, documenting, operating and administrating, as defined by the documentation source.

## Product target

Read the [target index](../apps/agent-relay/doc/target-spec/README.md) before framing product work. The target contains agreed requirements; technical candidates and unresolved questions do not belong in its volumes.
